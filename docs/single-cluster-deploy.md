# Single-cluster deployment

This guide describes how to deploy the quickstart on a single OpenShift
cluster with external integrations for Slack, ServiceNow, and Ansible
Automation Platform (AAP).

## Tested environment

* OpenShift Container Platform: 4.21
* Red Hat OpenShift AI: 3.4 / 3.5
* Ansible Automation Platform (AAP): 2.7

### Enable the Llama Stack Operator

On OpenShift AI 3.5, enable the Llama Stack Operator by setting `spec.components.llamastackoperator.managementState`
to `Managed` in the `DataScienceCluster` custom resource instance (`default-dsc`):

```bash
oc patch datasciencecluster default-dsc --type=merge \
  -p '{"spec":{"components":{"llamastackoperator":{"managementState":"Managed"}}}}'
```

This is not required with OpenShift AI 3.4.

### Enable Ansible Lightspeed

On AAP, enable Ansible Lightspeed by updating the `AnsibleAutomationPlatform` 
custom resource instance (`aap`) with:

```yaml
spec:
  lightspeed:
    disabled: false
    chatbot_config_secret_name: lightspeed-model-config
```

Connect an OpenAI-compatible model:

```yaml
apiVersion: v1
kind: Secret
metadata:
  name: lightspeed-model-config
  namespace: aap
type: Opaque
stringData:
  chatbot_model: "<model-id>"
  chatbot_url: "https://<model-endpoint>/v1"
  chatbot_token: "<model-api-token>"
```

Note: In our experience, the quality of the playbooks generated by Ansible
Lightspeed depends on the model used. Smaller models may produce
lower-quality playbooks.

## Environment variables

This quickstart is designed for deployment on your own cluster.
Export the following environment variables to match your environment.

### Target namespaces

1. `NAMESPACE`: the namespace in which the hub is installed. Default: `hub`.
2. `EDGE_NAMESPACE`: the namespace in which the edge is installed. Default: `dark-noc-edge`.

### Model endpoints

1. LLM URL, model ID, and token: `ADNR_LLM_URL`, `ADNR_LLM_ID`, `ADNR_LLM_TOKEN`.
2. Small Telco anomaly detection (AD) model: `ADNR_DETECT_INFERENCE_URL`.
   You can use: `https://ran-ml-service-external-fabio-model-service.apps.ai-dev02.kni.syseng.devcluster.openshift.com/v1/detect`
3. Small Telco root cause analysis (RCA) model: `ADNR_CLASSIFY_INFERENCE_URL`.
   You can use: `https://ran-rca-ml-service-external-fabio-model-service.apps.ai-dev02.kni.syseng.devcluster.openshift.com/v1/classify`

These two small-model endpoints are accessible from outside their hosting
cluster, so you can use them without deploying the models on your own cluster.

### AAP configuration

1. Set `AAP_TOKEN` to your AAP personal access token.
2. Set `ENABLE_AAP_MOCK` to `false`.
3. Set `ENABLE_LIGHTSPEED` to `true`.
4. Set `ENABLE_GITEA_UI` to `true` to access generated playbooks.

To obtain `AAP_TOKEN`, log in to the AAP platform gateway UI and navigate to
**Access Management → Users → your user → Tokens**. Create a token with
**Write** scope, leaving **Application** blank.

AAP 2.7 requires tokens created through platform gateway. See the
[AAP token documentation](https://docs.redhat.com/en/documentation/red_hat_ansible_automation_platform/2.7/secure-con_pat_removal_27).

### ServiceNow configuration

Create a ServiceNow personal developer instance by following the
[instance setup guide](https://www.servicenow.com/docs/r/application-development/get-dev-instance.html).
Set the connection details:

1. `SERVICENOW_INSTANCE_URL`: instance URL.
2. `SERVICENOW_USERNAME`: username.
3. `SERVICENOW_PASSWORD`: password.
4. `SERVICENOW_CALLER_NAME`: incident caller name, for example `noc-agent`.
5. Set `SERVICENOW_CREATE_RESOLVED` to `true` to also record automatically
   remediated (resolved) incidents in ServiceNow.
6. Set `ENABLE_SERVICENOW_MOCK` to `false` to use your ServiceNow instance.

### Slack configuration

Configure a Slack workspace and an app with a bot that can post to your
chosen channel. Follow the [Slack app setup guide](https://docs.slack.dev/app-management/quickstart-app-settings/)
to add the `chat:write` bot scope, install the app in your workspace, and
obtain its bot token. Invite the bot to the channel.

1. `SLACK_BOT_TOKEN`: bot token.
2. `SLACK_CHANNEL`: the channel where incident events will be posted.
3. Set `ENABLE_SLACK` to `true`.

## Deploy the quickstart

Log in to your OpenShift cluster:

```bash
oc login --token=xxxxx --server=https://api.xxx.openshift.com:6443
```

Deploy the hub:

* To deploy only Telco, set `ENABLE_NETWORK_REMEDIATION` to `false`.
* To deploy only Network, set `ENABLE_TELCO_ORAN` to `false`.

```bash
make helm-install
```

Deploy the edge directly with Helm:

```bash
EDGE_GITOPS=helm make edge-deploy
```

## Undeploy the quickstart

Delete both the hub and edge namespaces, including their workloads and persistent data:

```bash
make teardown
```
